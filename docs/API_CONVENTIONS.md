# API conventions

Status: specification v0.1, 11 November 2026.
Parent: [ENGINE.md](ENGINE.md). Methods behind these routes: [ENGINE_DESIGN.md](ENGINE_DESIGN.md).

The HTTP API is a client of `mandate-core`. Routes parse input, authenticate, authorize, build an `ExecutionContext`, call one engine method, and map the result. A route that contains a policy rule or a PayPal call is in the wrong layer.

The prototype's public list in `gateway/contract.py` is the compatibility target. Paths below keep those resources and add the ones the engine needs. Other applications connect to this list.

## Protocol

| Convention | Rule |
| --- | --- |
| Base path | `/v1` |
| Document | OpenAPI 3.1, generated by FastAPI, served at `/v1/openapi.json` |
| Resource ids | UUID strings |
| Money | Integer minor units in fields ending `_minor`, plus `currency` |
| Time | ISO-8601 UTC |
| Auth | `Authorization: Bearer` session token or `mdt_` API key |
| Tenant | Taken from the membership. A path or body organization id that disagrees is 404 |
| Correlation | `X-Request-Id`. The API generates one when the header is missing and returns it |
| Idempotency | `Idempotency-Key` required on policy activation, approval, and every commerce write |
| Pagination | `limit` default 50, maximum 200, and `cursor`. Responses include `next_cursor` |
| Errors | The body below. No provider stack traces |

Successful writes return the resource in a one-key envelope, as the prototype does: `{"policy": ...}`, `{"approval": ...}`, `{"payment": ...}`, `{"version": ...}`, `{"run": ...}`.

### Error body

```json
{
  "error": {
    "code": "over_budget",
    "message": "The catalog total is above the active policy maximum.",
    "request_id": "req_01H...",
    "details": {
      "evaluated_amount_minor": 85000,
      "maximum_amount_minor": 80000,
      "currency": "USD"
    }
  }
}
```

| Engine condition | HTTP |
| --- | --- |
| `unauthenticated` | 401 |
| `forbidden` | 403 |
| `not_found`, including a cross-tenant id | 404 |
| Validation, policy deny surfaced as a caller error, `compiler_invalid` | 400 |
| `compiler_overreach`, illegal version mutation | 409 |
| Idempotency key reused with a different body | 409 |
| `budget_exhausted` racing a lock | 409 |
| Provider timeout, row left `unknown` | 202 with the transaction body, or 504 when no row could be written. 202 is the case where the transaction exists and is `unknown` |
| Unexpected exception | 500 with code `internal`. The message is generic |

Policy denies during `evaluate` are not HTTP errors when the caller asked for a decision. They are `200` with `decision: deny`. They are HTTP errors when the caller asked to capture and the guard fails. Capture that voids returns `200` with `status: voided` and `reason_code: intent_mismatch`, because the system did what it promises. The client can see the void.

## Writes that require an idempotency key

`POST /v1/policies/{id}/activate`

`POST /v1/approvals`

`POST /v1/approvals/{id}/approve`

`POST /v1/approvals/{id}/reject`

`POST /v1/payments`

`POST /v1/payments/{id}/authorize`

`POST /v1/payments/{id}/capture`

`POST /v1/payments/{id}/void`

`POST /v1/payments/{id}/refund`

The same key and the same body return the original resource and do not call the provider again. The same key and a different body return 409 `idempotency_conflict`.

## Resources by release

Routes appear in the release that has the subsystem. Earlier releases still serve `/health` and `/v1`.

### v0.1

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/health` | Process and database connectivity |
| GET | `/v1` | Name, engine package version, and the resource list |

### v0.2 to v0.5, agents and skills

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/v1/agents` | List agents and their published versions |
| POST | `/v1/agents` | Create an agent definition |
| POST | `/v1/agents/{id}/versions` | Publish an immutable version |
| GET | `/v1/agents/{id}/versions/{version_id}` | Read one version |
| GET | `/v1/skills` | List skills that can be attached. PayPal is absent |
| POST | `/v1/skills` | Register a skill definition. In-process, trusted code only |
| POST | `/v1/agents/{id}/runs` | Create a run for a published version |
| POST | `/v1/runs/{id}/resume` | Resume from the checkpoint |
| POST | `/v1/runs/{id}/cancel` | Stop at the next super-step. Does not void payments |
| GET | `/v1/runs/{id}` | Run, trace, and proposal ids |

The prototype path `POST /v1/agents/agt_buyer/run` is kept as a compatibility alias until the porting gate, then removed. New clients use `POST /v1/agents/{id}/runs`.

Publish body:

```json
{
  "prompt": "string",
  "model": "gpt-4o-mini",
  "provider": "openai",
  "temperature": 0,
  "skill_ids": ["uuid"]
}
```

A version is immutable. There is no PATCH of `prompt` or `skill_ids`.

### v0.3, models

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/v1/models` | Providers enabled for the organization, and capability metadata |
| PUT | `/v1/settings/model` | Set the organization default provider and model. The key, if sent, is write-only |

`GET /v1/config` remains for the studio shell: `paypal_mode`, sandbox client id, whether a model key is configured, and the model name. It never returns a secret.

### v0.6, policy

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/v1/policies` | Compile an instruction into a draft version |
| GET | `/v1/policies` | List versions. Active versions are not edited in place |
| POST | `/v1/policies/{id}/activate` | Activate a draft that has no ambiguities |
| POST | `/v1/decisions` | Evaluate one catalog SKU. The catalog owns the price |
| POST | `/v1/proposals` | Alias of the decision write used by the prototype |

Compile body: `{"instruction": "string"}`.

Decision body: `{"policy_id": "uuid", "sku": "string"}`. A `suggested_unit_amount_minor` field, if a client still sends it, is ignored and reported in the trace.

Activation is the only route that sets a policy active. The compile route rejects a model status.

### v0.7, approval

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/v1/approvals` | Open an approval for one proposal |
| POST | `/v1/approvals/{id}/approve` | Bind the caller to that snapshot |
| POST | `/v1/approvals/{id}/reject` | Reject or revoke |
| GET | `/v1/approvals` | Inbox for the caller |
| GET | `/v1/approvals/{id}` | Snapshot, hash, expiry, and status |

Approve body may be empty. The server loads the proposal. The client does not send the amount.

### v0.8, commerce

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/v1/payments` | Reserve budget and create a provider order for the approved amount |
| POST | `/v1/payments/{id}/authorize` | Authorize the provider order this payment already created |
| POST | `/v1/payments/{id}/capture` | Capture when the catalog hash still matches. Otherwise void |
| POST | `/v1/payments/{id}/void` | Void an open authorization |
| POST | `/v1/payments/{id}/refund` | Refund a capture, full amount in v0.8 |
| GET | `/v1/payments/{id}` | Transaction, attempts, and reason code |
| POST | `/v1/providers/paypal/webhook` | Verified provider events only |

Payment create body: `{"proposal_id": "uuid", "approval_id": "uuid"}`.

Authorize body: `{"order_id": "string"}`. The server checks `order_id` equals the order it created.

### v0.9, studio support and developers

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/v1/timeline` | Audit timeline for an aggregate, `type` and `id` query |
| POST | `/v1/api-keys` | Create a key. The secret is in this response only |
| POST | `/v1/api-keys/{id}/revoke` | Revoke |
| GET | `/v1/usage` | Token counts for the organization |

Webhooks to customer URLs, the JavaScript SDK, and the Python SDK ship in this release and speak this same `/v1` surface. They do not grow a private route.

## Catalog and simulation routes

`GET /v1/catalog` returns the merchant catalog the skill reads. Prices are minor units.

Policy simulation, `POST /v1/policies/{id}/simulate`, is specified now and implemented after v0.6 is deterministic. It evaluates stored proposals against a draft version and activates nothing.

## Compatibility with the running prototype

Until the porting gate, `gateway/main.py` keeps serving the current process on port 8000. The new API uses a different port during development, 8001, so both can run. The new API's `/v1` resource list is allowed to be a subset until the release that owns each route. It is not allowed to give a route a different meaning.

| Prototype behavior | New API |
| --- | --- |
| Envelope keys `policy`, `approval`, `payment`, `version` | Same keys |
| Error `{"code", "message"}` | Extended with `error.request_id` and `error.details`. `code` and `message` stay |
| `Idempotency-Key` on payment create | Required on every commerce write |
| PayPal client id in config when sandbox | Kept. Secret never added |
